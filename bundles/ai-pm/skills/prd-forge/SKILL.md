# PRD 结构化起草

## 一、何时调用
- 由对应数字员工按岗位任务触发；夜班任务按编排窗口执行。

## 二、输入契约
- 行业包种子数据/运行时事件流；外部信息必须带来源回执。

## 三、执行步骤
1. 读取需求与来源上下文，区分给定事实、设计假设和待确认问题；明确给谁用、解决什么问题及相对现有方式的可验证价值。
2. 按背景/目标/方案/边界/验收展开，至少给 3 个具体用户场景，每个有角色、触发、前置、行为及可观察结果；给功能实施的 P0/P1/P2 清单和不用该功能的后果，不能只定义工单紧急程度而漏掉功能分级。
3. 字段逐项明确类型、必填时点、默认值、是否可空、合法值、唯一性/幂等，以及在各状态/角色下的读写和流转权限；验收覆盖正常、空值/最大值、错误、权限与重复提交。
4. 交付前做一致性自检：场景、字段表、状态机、权限和验收必须使用同一规则。例如“创建即100%有负责人”不能与“创建可空、分诊后必填”同时成立；发现矛盾先改为一个明确合同，再输出，不把互相冲突的方案当已完成需求。
5. 范围、日期、工期和性能阈值没有材料依据时标设计假设或待确认，不把会议中的未知事项扩写成已定事实。验收结果未执行时写待验证。
6. 生成完整 Markdown 产物；只有实际文档库写入工具返回可核对回执后才称“已入库”。仅在隔离目录生成文件时如实写“已生成文件，未写真实知识库/文档库”。

## 四、边界与围栏
- 权限面：写文档库（L1）。
- 写入级动作严格走 preset 的 fence_bindings；引用外部信息必须标注来源。
- 绝不编造：无工具回执的事实标「未核实」。

## 五、与其他技能的协作
- 产出进晨报素材池；异常与高威胁项挂审批台（review-console）。
