# WorkLoom PM：真实评测、失败与能力边界

本报告记录从 WorkLoom IM `e5d76398484cac7d8ac50b6c27905765a59fd50f` 派生的 PM 产品在本机隔离环境中的评测。它区分代码实现、离线夹具、真实模型回执、文件交付与内容质量；不把一类证据换算成另一类。

本轮结论是：**已形成可运行的 PM 团队任务图、真实岗位产物和受限 DSH 研发链路；第一轮真实复杂项目仍为 0/2 端到端通过，不能宣称全流程自主交付已经达标。** 单岗最新文件交付 13/14 包含 PM 运行系统之外的工程修复和显式重跑，而且独立逐份阅读发现了内容错误。这些失败没有改写为成功。[A/B]

## 两项复杂项目的完整失败路径

两个目标均包含 18 段背景、明确四角色依赖链、零依赖 ESM 模块、至少六条非 skip 自测、正常/空/Unicode/异常/权限边界，以及交付文档末尾标记。独立业务断言预先由评测者编写，不用生成代码自己的测试作为唯一依据。[A/B]

1. **Todo 长目标**：需求节点完成；开发节点写出了 `todo.mjs` 与 `todo.test.mjs`，但原 4 次模型上限在最终回答前阻断。研发、评测、文档链没有完成。随后对保留的半成品做免费 OS 隔离验证：独立模块契约 2/2 通过；模型自写 16 个测试中 15 通过、1 失败，失败是把组合 emoji 的 UTF-16 长度误当成码点数。不能把“上限修为 8”当作这个项目已通过。[B]
2. **Ledger 长目标**：经理生成五节点，违反目标明确的四节点限制；模块节点已完成，测试节点被总 token 预算拒绝，后续未执行。旧适配器把该 429 误归普通 DSH 失败。保留模块的独立契约 2/2 通过，仅证明该模块的已断言行为，不能补齐不存在的测试、评测和交付文档。[B]

评测入口会把四角色唯一性、依赖可达性、实际文件、hash、最终状态、真实计量、独立代码断言和长目标尾标记分别记录。即使运行状态为 completed，只要明确的计划约束不满足，评测仍为失败。运行系统的结构合同不保证理解任意自然语言约束；语义偏离必须保留为真实失败。[A]

## 第一轮预算与凭据

本轮所有收费 HTTP 经父进程 loopback 代理，模型 key 只存在该进程；产品 server 和 DSH 仅持随机本地代理哨兵。预算覆盖每个物理请求，含失败和重试；代理自身不自动重试。官方 tokenizer 与冻结编码 recipe 前置计算输入，加显式输出上限与协议余量后预占；计量未知冻结后续请求。[A/B]

第一轮实际 **40 次物理请求 = 39 次模型 + 1 次 Search**；模型回执累计 **167876 token**。保守额度累计 **299563 token**；按本轮冻结的人民币 0.02 元/千 token 预算率，预占估算 **5.9913 元**、已知模型用量折算 **3.3575 元**。这是预算估算，不是供应商账单；搜索的实际账单价格没有在本轮对账。没有未结算请求或未知用量。[B]

硬闸为 40 次、30 万保守 token、120 元估算与 45 分钟付费窗口；同 run 重启保留原账本与原时钟，不能清零。免费状态/UI 读取可以在窗口后继续，但新增付费请求仍被拒。再次真实复测需要新的明确预算授权，不能换 runId 绕过。普通部署直接配置 provider 并不自动获得本轮专用评测代理的全局预算保证。[A/B]

源码与公开打包只携模型集成及配置方式，不携本任务真实 key。开发进程通过运行时变量注入；正式分发的凭据策略与签名发行需单独配置。客户端 JS、README、日志与 Git 历史都不应存入真实 key。[A]

## 复跑入口

离线回归从仓库根执行：

```sh
pnpm typecheck
pnpm test
pnpm test:pm-dsh
node --test apps/server/src/industry/ai-pm/acceptance/metrics.node-test.mjs
```

真实 PG 用例须显式 `RUN_DB_TESTS=1`，并同时提供本任务隔离端口的 owner/app/gateway 连接。未配置时跳过的用例须保留为 skip，不能写成真实数据库通过。不要对现有任务库重跑 seed/reset 来制造干净成绩。

`pnpm pm:eval` 对应 `apps/server/src/industry/ai-pm/acceptance/evaluate.mts`，仅在已授权且由持久化 loopback 预算代理保护的启动环境执行。`PM_EVAL_PHASE` 追加修复阶段；`PM_EVAL_ONLY` 可显式选择 case；已通过的员工不会自动重复收费。真实评测失败并不通过退出码或覆盖旧 JSON 来消失；逐例结果与实际请求账本都必须读取。

## RDAS、ADR/HIR 与验收债

本轮采用 RDAS 的证据与预算纪律，并保留固定 276 项清单分母。专项测试数量不能映射成“276 项全部通过”。尚未执行的跨平台、生产、可访问性、真实用户研究、长跑、外部连接器与签名发行条目均为 not-run/manual-missing，最终总报告给出逐项状态。[D]

U 域有真实桌面/移动任务入口、成员身份、空/错/加载/只读状态与截图证据；没有真实用户研究、读屏器与所有浏览器结论。O 域有任务合同、依赖、回执、代码断言与失败证据；复杂交付没有全绿。P 域只证明隔离本机模型被真实触发、产物与配额可回读，不能写“客户生产环境通过”。[B/D]

ADR-0/1/2 与 HIR 不能直接用 13/14 填充：本轮有操作者修代码、重跑与语义复核，不是零干预业务实验；没有完整人员分钟、同质对照样本与真实客户业务价值。HIR-NI、H3+H4、HMPO 和 AVR 象限保留未充分测量，不伪造“节省多少人工”。[B/D]

验收债：修后真实模型重测、复杂任务完整输出和独立断言、更多语义标注样本、自然语言计划约束的失败处理、其它 OS/依赖项目的验证后端、真实外部工具与生产数据、签名安装包与供应商账单对账。每项仍须独立证据，不能用本轮有限成功替代。
